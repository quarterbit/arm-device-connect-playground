SUNHAUS · a Device Connect
smart-home demo

One house. Eleven appliances. One agent. A full day in three minutes. Every device is its own process; none knows about the others in advance. A home-energy agent discovers them over Zenoh and orchestrates the whole day — laundry and hot water on the solar peak, a cloud front handled, an EV charged before it reaches the driveway.

02What's real, what's simulated

The honest split. The Device Connect layer and the agent are exactly what a production deployment runs. Only the hardware behind each driver is a simulation.

05Run it yourself

The whole house comes up with one command. Each appliance is a real process that finds the others over Zenoh; the agent discovers them and takes over.

Launch the house

# from sunhaus/, in a venv with the two
# device-connect packages + eclipse-zenoh
pip install -e .

python -m runner.demo            # 3-min day
python -m runner.demo --speed 6x # 30-sec run
python -m runner.demo --tail     # + live bus log

Watch the real bus & run the tests

# in a second terminal — genuine Zenoh
# event traffic, subscribe("event(*)")
python -m runner.tail

# 17 tests, no bus needed
python -m pytest

06How it fits together

Twelve processes on one machine, no shared memory, no coordinator — only a Zenoh device-to-device bus and a simulated-day clock each derives locally.

   inverter-01   battery-01   wallbox-01   ev-blue   ev-red   heatpump-01
   hvac-01       washer-01    climate-01   weather-01   meter-01
        │   each is a DeviceRuntime — a Zenoh peer   │
        └───────────────┬────────────────┬───────────┘
                        │  Zenoh D2D bus  │      (multicast scouting, no broker)
                        │                 │
                    agent-home        runner.tail
           discover() · invoke() · subscribe("event(*)")

Devices state needs; the agent owns the schedule. A heat pump asks for a cheap window, a washer advertises a deadline, a car announces it's heading home — the agent answers with an RPC. Request events repeat until served, and the plug-in is confirmed over RPC, so the demo stays reliable over best-effort D2D. Full write-up in architecture.md and CONCEPT.md.
